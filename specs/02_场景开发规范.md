# 场景开发规范

> 本文档为只读文档。
> Godot 4.x 场景（`.tscn`）设计与组织规范。AI 在**阶段 7（架构设计场景树）**与**阶段 8（搭建场景）**时**必须**加载并遵循本规范。
> 每条含：规范说明 + 正例（✅）+ 反例（❌）。

---

## 一、场景组织

### 1. 场景按实体类型分目录

**说明**：`scenes/` 下按**游戏实体**（actors/levels/objects/ui）组织，**禁止**按节点类型分。

**正例**（✅）：
```
scenes/
├── actors/player/player.tscn
├── levels/level_01.tscn
└── ui/main_menu.tscn
```

**反例**（❌）：
```
scenes/
├── characterbody2d/player.tscn   # 按节点类型分，违反约定
├── area2d/chest.tscn
```

### 2. 一场景一职责

**说明**：每个场景只承担一个职责；复杂实体拆成多个子场景/组件，避免「God scene」。

**正例**（✅）：
```
Player.tscn         # 玩家编排
├── HealthComponent.tscn   # 血量逻辑独立
└── Weapon.tscn            # 武器逻辑独立
```

**反例**（❌）：
```
Game.tscn   # 塞入玩家/敌人/UI/音效全部逻辑，难维护
```

### 3. 场景自包含（prefab 思想）

**说明**：场景应是可复用、自包含单元，能在任何地方独立实例化并正常运行，不依赖外部全局状态。

**正例**（✅）：`enemy.tscn` 自带 Sprite/Collision/AI 脚本，拖入任意关卡即可工作。

**反例**（❌）：`enemy.tscn` 必须读取某个全局变量、或依赖父节点特定名称才能工作。

### 4. 组合优于继承

**说明**：复杂实体优先用组件**组合**构建，而非深层继承链。

**正例**（✅）：
```
Player = CharacterBody2D + Health + Movement + Weapon
```

**反例**（❌）：
```
Player → Character → Actor → Node   # 多层继承，耦合重、难调整
```

## 二、根节点与脚本

### 5. 根节点类型匹配职责

**说明**：按实体物理特性选根节点类型——可控角色 `CharacterBody2D/3D`、触发区域 `Area2D/3D`、纯视觉 `Node2D/Sprite2D`、UI 用 `Control` 系。

**正例**（✅）：敌人 `CharacterBody2D`、宝箱 `Area2D`、按钮 `Button`、背景 `Sprite2D`

**反例**（❌）：所有实体根节点都用 `Node2D`，再手动加物理/碰撞，丢失内置能力。

### 6. 主脚本挂根节点且与场景同目录

**说明**：场景主控脚本挂在**根节点**；脚本与场景同名、放同一目录（co-locate）。

**正例**（✅）：
```
scenes/actors/player/
├── player.tscn        # 根 CharacterBody2D 挂 player.gd
└── player.gd
```

**反例**（❌）：脚本挂在子节点；或脚本放 `scripts/` 与场景分离存放。

### 7. 根脚本定义 class_name

**说明**：根脚本定义 `class_name`（PascalCase），与场景语义一致，便于类型标注与全局引用。

**正例**（✅）：
```gdscript
class_name Player
extends CharacterBody2D
```

**反例**（❌）：`player.gd` 无 `class_name`，别处引用只能用字符串路径或弱类型。

## 三、组件与嵌套

### 8. 用组件场景构建实体

**说明**：可复用能力（血量/碰撞/移动）封装为独立组件场景，实体根脚本负责编排（连接信号、转发调用）。组件即可复用子场景，命名以**功能名**为准（如 `health.tscn`），**不必**加 Component 后缀。

**正例**（✅）：
```
Player.tscn (player.gd 编排)
├── Health (health.tscn)
├── Hitbox (hitbox.tscn)
└── Movement (movement.tscn)
```
```gdscript
func _ready() -> void:
    $Health.died.connect(_on_died)
    $Hitbox.hit_received.connect($Health.take_damage)
```

**反例**（❌）：把血量、碰撞、移动全写进 `player.gd`，无法被敌人/NPC 复用。

### 9. 优先抽取可复用子场景

**说明**：**优先**把可复用的功能单元抽成独立子场景再实例化，而不是直接在场景里堆积大量节点——以便复用与维护。判断标准：一组节点若可能被重复使用、或承担独立职责，就应抽成子场景。

**正例**（✅）：`Player.tscn` 由 `weapon.tscn`、`hud.tscn`、`health.tscn` 等子场景实例组合而成。

**反例**（❌）：`Player.tscn` 手动堆叠数十个节点未抽取，难复用、难维护、编辑器卡顿。

### 10. 变体用场景继承

**说明**：同类实体的多个变体（slime/goblin）用**继承**自 base 场景，覆盖纹理与数值；禁止复制粘贴改。

**正例**（✅）：
```
enemy_base.tscn          # 基类场景
├── slime.tscn (inherits)   # 覆盖纹理/数值 + slime.gd extends EnemyBase
└── goblin.tscn (inherits)
```

**反例**（❌）：复制 `enemy_base.tscn` 改名 `slime.tscn`，后续 base 修改无法同步。

## 四、节点引用与命名

### 11. 节点语义化命名

**说明**：节点名描述其作用（PascalCase），**禁止**保留默认 `Node2D`/`Node`。

**正例**（✅）：`Health`、`WeaponMount`、`SpawnPoint`、`Camera2D`

**反例**（❌）：`Node2D`、`Node2D2`、`Sprite`、`Area2D3`（默认名/重复名）

### 12. 关键节点启用唯一名 %

**说明**：需跨层级或稳定引用的关键节点开启 unique name（`%`），避免深路径在重构时断裂。

**正例**（✅）：
```gdscript
@onready var player: Player = %Player
@onready var health_bar: ProgressBar = %HealthBar
```

**反例**（❌）：
```gdscript
@onready var bar = $UI/Panel/Container/VBox/HealthBar   # 深路径，一改就断
```

### 13. 场景树层级保持浅（≤ 3-4 层）

**说明**：避免过深嵌套；深层级用子场景或 `%` 引用扁平化。

**正例**（✅）：扁平结构 + `%` 唯一名 + 组件子场景。

**反例**（❌）：`$A/B/C/D/E` 五层以上路径访问节点。

## 五、场景间通信

### 14. 信号向上、调用向下（signal up, call down）

**说明**：子节点发信号，父节点连接并调用子方法；**禁止**子节点反向调用父节点方法。

**正例**（✅）：
```gdscript
# 子 HealthComponent
signal died

# 父 Player
func _ready() -> void:
    $HealthComponent.died.connect(_on_died)
```

**反例**（❌）：
```gdscript
# 子节点直接调父 —— 紧耦合
func die() -> void:
    get_parent().on_child_died()
```

### 15. 兄弟节点经父或 group 中转

**说明**：兄弟节点不直接互访，通过共同父节点转发信号，或用 group。

**正例**（✅）：Weapon 发 `ammo_depleted`，Player 监听后更新 UI。

**反例**（❌）：
```gdscript
# weapon.gd 直接操作兄弟 UI 节点
$UI/AmmoLabel.text = "0"
```

### 16. 跨场景用 group 或 autoload 事件总线

**说明**：跨场景边界通信用 group 或 autoload 事件总线；**禁止**全树搜索。

**正例**（✅）：
```gdscript
for enemy in get_tree().get_nodes_in_group("enemies"):
    enemy.take_damage(damage)
# 或 autoload 事件总线：EventBus.player_died.emit()
```

**反例**（❌）：
```gdscript
var enemy = get_tree().root.find_child("Enemy", true, false)  # 全树搜索，慢且脆弱
```

## 六、配置与解耦

### 17. 用 @export 暴露场景可配置项

**说明**：场景可调参数用 `@export` 暴露，实例化时在编辑器单独配置；禁止硬编码。

**正例**（✅）：
```gdscript
@export var move_speed: float = 100.0
@export var patrol_points: Array[Node2D] = []
# 不同敌人实例可设不同速度
```

**反例**（❌）：
```gdscript
const MOVE_SPEED = 100.0   # 写死，所有实例相同，无法在编辑器调
```

### 18. 子场景不依赖父节点结构

**说明**：子场景不应假设父节点类型/路径；需要外部信息时用 `@export` 注入或信号向上传递。

**正例**（✅）：
```gdscript
# weapon.gd —— 依赖注入
@export var wielder: CharacterBody2D
# 或 func setup(stats: CharacterStats) -> void:
```

**反例**（❌）：
```gdscript
# weapon.gd 假设 owner 是 Player 并直接调其方法
func attack() -> void:
    (owner as Player).consume_ammo()   # 绑死父类型，无法复用
```

## 七、命名细则

### 19. 组件命名不加 Component 后缀

**说明**：组件本质是可复用子场景，命名以**功能名**为准（节点/类名 PascalCase、文件名 snake_case），**禁止**加 `Component` 后缀。

**正例**（✅）：
- 场景文件：`health.tscn`、`hitbox.tscn`、`movement.tscn`
- 节点 / 类名：`Health`、`Hitbox`、`Movement`

**反例**（❌）：
- 场景文件：`health_component.tscn`、`HealthComponent.tscn`
- 节点 / 类名：`HealthComponent`、`MovementComponent`

## 附：场景自查清单

新建/修改场景提交前逐条核对：

- [ ] 场景按实体类型放目录（actors/levels/objects/ui），非按节点类型
- [ ] 单一职责；复杂实体已拆组件/子场景，无 God scene
- [ ] 场景自包含，可独立实例化运行
- [ ] 根节点类型匹配职责；主脚本挂根节点且与场景同目录
- [ ] 根脚本有 `class_name`；变体用继承非复制
- [ ] 节点语义化命名（无默认 Node2D）；关键节点用 `%` 唯一名
- [ ] 层级 ≤ 3-4，无深路径；通信遵循 signal up / call down
- [ ] 可调参数用 `@export`；子场景不依赖父结构
- [ ] 场景存为 `.tscn`（文本，可 git diff），**禁止** `.scn`（二进制）
- [ ] 组件命名以功能名为准，无 Component 后缀（`health.tscn` / `Health`）
